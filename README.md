# 지원사업 공고 브리핑

34개 공공기관 게시판을 매일 아침 훑어서, 키워드에 맞는 **신규 공고만** 골라 메일로 보냅니다.

- **평일 아침 10:00 (한국시간)** 자동 발송 · 주말 제외
- **마감된 공고는 제외** — 목록·제목·상세 페이지 세 군데에서 마감일을 확인합니다
- **게시일 기준 최근 10일** 이내 공고만
- **한 번 보낸 공고는 다시 안 보냄**
- 마감일을 읽을 수 없는 공고는 `마감일 확인필요`로 표시해서 포함
- 포함 키워드 / 제외 키워드 / 수신자 / 기관 목록 전부 파일에서 수정

---

## 두 가지가 나옵니다

**1. 매일 아침 메일** — 그날 새로 찾은 공고만. 이미 보낸 건 안 옵니다.

**2. 누적 엑셀** — 지금까지 보낸 공고 전부. *언제 찾았는지*가 첫 칸입니다.

| 발견일 | 기관 | 공고명 | 게시일 | 마감일 | 매칭 키워드 | 링크 |
|---|---|---|---|---|---|---|
| 2026-09-08 | 부산테크노파크 | 시니어 돌봄로봇 실증 참여기업 모집 | 2026-09-08 | 2026-09-30 | 시니어, 돌봄, 실증 | 바로가기 |
| 2026-09-07 | 부산정보산업진흥원 | AX 에이지테크 시장확산 지원사업 | 2026-09-01 | 2026-09-19 | 에이지테크, AX | 바로가기 |

- 저장소 최상단의 **`공고누적.xlsx`** — 아무 때나 열어볼 수 있습니다
- **월·수·금 아침 메일에 첨부**로도 옵니다 (매일 첨부하면 메일함이 무거워져서)
- 최신순 정렬, 첫 줄 고정, 필터 걸려 있음, 링크는 클릭하면 원문으로

원본은 `state/archive.csv`에 텍스트로 쌓이고 매일 커밋됩니다. 엑셀은 여기서 만들어집니다 — 엑셀을 매일 커밋하면 저장소가 금방 무거워지고 변경 내역도 안 보이기 때문입니다.

갱신 요일을 바꾸려면 `config.yaml`의 `archive_attach_weekdays` (0=월 … 6=일):

```yaml
archive_attach_weekdays: [0, 2, 4]      # 월·수·금 ← 현재
# archive_attach_weekdays: [0,1,2,3,4]  # 평일 매일
# archive_attach_weekdays: [0]          # 월요일만
```

> **`state/archive.csv` 는 실행할 때마다 매번 갱신됩니다.** 요일 설정은 *보기용 엑셀*과 *메일 첨부*에만 적용되므로, 어느 요일에 찾은 공고든 기록에서 빠지는 일은 없습니다.
> 최신 상태를 아무 때나 보고 싶으면 Actions 실행 결과의 **Artifacts** 안에 매번 만들어지는 `공고누적.xlsx` 를 받으시면 됩니다.

누적 기능을 끄려면 `archive_enabled: false`.

## 설치 (한 번만)

### 1단계. 저장소 만들기

GitHub에서 새 저장소를 만들고(Private 권장), 이 폴더의 파일을 전부 올립니다.

```bash
git init
git add .
git commit -m "init: 공고 브리핑"
git branch -M main
git remote add origin https://github.com/<계정>/<저장소>.git
git push -u origin main
```

> 웹으로 올려도 됩니다: 저장소 → Add file → Upload files → 폴더째 드래그.
> 단, `.github` 폴더는 웹 업로드에서 숨겨질 수 있으니 확인하세요.

### 2단계. Gmail 앱 비밀번호 만들기

일반 Gmail 비밀번호로는 안 됩니다. **앱 비밀번호**가 따로 필요합니다.

1. https://myaccount.google.com/security 접속
2. **2단계 인증**을 켭니다 (이미 켜져 있으면 넘어감)
3. https://myaccount.google.com/apppasswords 접속
4. 이름을 아무거나(예: `공고브리핑`) 넣고 생성
5. 나오는 **16자리 문자열**을 복사 (공백은 빼도 되고 넣어도 됩니다)

### 3단계. GitHub Secrets 등록

저장소 → **Settings** → **Secrets and variables** → **Actions** → **New repository secret**

| 이름 | 값 | 필수 |
|---|---|---|
| `SMTP_USER` | 보내는 Gmail 주소 (예: `qjagh6414@gmail.com`) | **필수** |
| `SMTP_PASSWORD` | 2단계에서 만든 앱 비밀번호 16자리 | **필수** |
| `MAIL_TO` | 받는 사람들 (쉼표 구분). **등록하면 `config.yaml`의 recipients 는 완전히 무시됩니다** | 선택 |
| `DATA_GO_KR_KEY` | 공공데이터포털 인증키 | 선택, 나중에 |

> **Secrets를 등록하기 전에도 프로그램은 정상적으로 돌아갑니다.**
> 메일만 안 보내고, 결과를 Actions의 Artifacts에 파일로 남깁니다.
> 나중에 Secrets를 추가하면 그 다음 실행부터 자동으로 발송이 시작됩니다.

### 4단계. Actions 켜기

저장소 → **Actions** 탭 → `I understand my workflows, go ahead and enable them` 클릭

### 5단계. 먼저 진단 한 번 돌리기 ⭐

**이걸 꼭 먼저 하세요.** 34개 기관 중 어디가 되고 어디가 막히는지 알려줍니다.

**Actions** → 왼쪽에서 **기관 수집 진단** → **Run workflow** → 초록 버튼

2~3분 뒤 실행 화면 아래에 표가 나옵니다:

| 기관 | 상태 | 수집 | 최신 게시일 | 비고 |
|---|---|---|---|---|
| 부산정보산업진흥원 | ✅ | 15건 | 2026-09-07 | 마감일 파싱 15/15 |
| 전북테크노파크 | ❌ | — | — | 연결 시간 초과 |

- ✅ 정상
- ⚠️ 접속은 되는데 목록을 못 읽음 → 선택자 지정 필요
- ❌ 접속 실패 → 차단이거나 URL이 바뀐 것

**이 표를 저에게 보내주시면 실패한 기관을 고쳐서 다시 드리겠습니다.**

### 6단계. 시험 발송

**Actions** → **매일 공고 브리핑** → **Run workflow** → `dry_run` 체크 해제 → 실행

메일이 오면 끝입니다. 이후로는 매일 아침 8시에 자동으로 옵니다.

## 구글시트로 관리하기 (동료와 같이 쓸 때)

GitHub에서 YAML을 고치는 게 부담스러운 동료가 있다면, **키워드·수신자·기관을 구글시트에서 관리**할 수 있습니다.

**인증키도 서비스계정도 필요 없습니다.** 시트를 '웹에 게시'하면 나오는 주소를 읽는 방식이라 **어느 구글 계정의 시트든 상관없습니다.**

### 1. 시트 만들기

동봉된 **`공고브리핑_설정시트.xlsx`** 를 구글 드라이브에 올리고 → **파일 → Google 스프레드시트로 저장**.

`포함키워드` / `제외키워드` / `기관` 탭 세 개가 지금 설정 그대로 채워져 나옵니다.

| 탭 | 하는 일 |
|---|---|
| 포함키워드 | 제목에 이 말이 하나라도 있으면 메일에 넣습니다 |
| 제외키워드 | 제목에 이 말이 있으면 무조건 버립니다. **포함보다 우선** |
| 기관 | 기존 기관은 `사용` Y/N으로 켜고 끄기. 맨 아래에 기관명+주소를 쓰면 새 기관 추가 |

세 탭 모두 `사용` 칸에 `N`을 적으면 그 줄만 무시됩니다. 지우지 말고 꺼두세요.

**수신자 탭은 일부러 넣지 않았습니다.** 웹에 게시한 시트는 주소를 아는 사람이면 누구나 볼 수 있어서, 이메일은 `config.yaml`의 `recipients`로 관리하는 편이 안전합니다.
굳이 시트로 옮기려면 `python -m tests.make_sheet_template --with-recipients` 로 수신자 탭이 포함된 템플릿을 만들 수 있습니다.

### 2. 시트를 읽을 수 있게 열어주기

GitHub 서버는 구글 로그인을 못 합니다. 그래서 로그인 없이 읽히게 해야 합니다. **둘 중 하나**만 하면 됩니다.

**방법 A — 링크 공유 (간단, 권장)**

시트 우측 상단 **공유** → 일반 액세스를 **`링크가 있는 모든 사용자`** + 역할 **`뷰어`** → 완료.

그다음 브라우저 주소창의 주소를 탭마다 복사해서 `config.yaml`에 넣으면 됩니다.
`.../edit?gid=441632177#gid=441632177` 형태 그대로 넣어도 됩니다 — **프로그램이 알아서 CSV 주소로 바꿉니다.**

**방법 B — 웹에 게시 (탭 단위로 공개 범위를 좁히고 싶을 때)**

**파일 → 공유 → 웹에 게시** → 게시할 항목에서 **탭 하나**를 고르고 → 형식을 **쉼표로 구분된 값(.csv)** → **게시**.

나오는 주소를 복사합니다. **탭마다 따로 해야 합니다** (탭 3개면 3번).

> 방법 A는 시트 전체가 링크로 열리고, 방법 B는 게시한 탭만 열립니다. 어느 쪽이든 **읽기 전용**이라 남이 고칠 수는 없습니다.

### 3. config.yaml에 주소 붙여넣기

```yaml
sheet:
  enabled: true                                    # false → true
  include_keywords_url: "https://docs.google.com/.../pub?gid=0&single=true&output=csv"
  exclude_keywords_url: "https://docs.google.com/.../pub?gid=11111&single=true&output=csv"
  institutions_url:     "https://docs.google.com/.../pub?gid=22222&single=true&output=csv"
  recipients_url: ""     # 비워둠 → config.yaml 의 recipients 사용
```

이제 동료가 시트만 고치면 **다음 날 아침부터 반영**됩니다. GitHub은 건드릴 필요가 없습니다.

### 알아두실 것

> ⚠️ **'웹에 게시'한 시트는 주소를 아는 사람이면 누구나 볼 수 있습니다.**
> 키워드나 기관 목록은 상관없지만, **동료 이메일 주소는 노출됩니다.**
> 그게 곤란하면 `recipients_url`을 비워두고 수신자는 `config.yaml`로 관리하세요.
> 탭마다 독립적이라 키워드·기관만 시트로 두는 게 가능합니다.

- 시트를 못 읽으면(주소 오타, 게시 해제, 구글 장애) **저장소 설정으로 그냥 진행**합니다. 브리핑이 멈추지 않습니다. 어느 쪽을 썼는지는 메일 하단과 실행 로그에 나옵니다.
- 시트 반영은 **다음 실행부터**입니다. 즉시 확인하려면 Actions에서 수동 실행하세요.
- 기관 탭에서 **기관명을 고치면 안 됩니다.** 이름으로 기존 기관을 찾기 때문에, 이름이 바뀌면 연결이 끊어져 새 기관으로 취급됩니다.
- 기관 탭의 `주소` 칸은 기존 기관에서는 **비워두세요.** 선택자 같은 세부 설정은 `institutions.yaml`이 계속 관리합니다. 주소는 새 기관을 추가할 때만 씁니다.
- 게시 주소가 CSV가 아니라 HTML을 돌려주면 형식을 `.csv`로 안 고른 것입니다.

## 매일 쓰면서 고치는 법

### 받는 사람 추가

`config.yaml` 을 GitHub 웹에서 열고 (연필 아이콘) 한 줄 추가한 뒤 **Commit changes**.

```yaml
recipients:
  - qjagh6414@gmail.com
  - 동료이름@zeroweb.co.kr      # ← 앞에 공백 2칸 + 하이픈 + 공백 1칸
```

> **추가했는데 메일이 안 갈 때 — 먼저 이것부터 확인하세요.**
> GitHub Secrets 에 `MAIL_TO` 가 등록돼 있으면 **`config.yaml` 의 recipients 는 통째로 무시됩니다.**
> Settings → Secrets and variables → Actions 에서 `MAIL_TO` 가 있는지 보세요.
> 있으면 거기에 쉼표로 추가하거나, `MAIL_TO` 를 지우면 config.yaml 이 다시 쓰입니다.

실행 로그 맨 위에 **어디서 읽었고 누구에게 갈 것인지** 찍힙니다:

```
-- 수신자 출처: config.yaml
     → qjagh6414@gmail.com
     → 동료이름@zeroweb.co.kr
```

`수신자 출처: MAIL_TO 시크릿 (config.yaml 의 recipients 는 무시됨)` 이라고 나오면 위 경우입니다.
주소에 오타가 있으면 `[!] 주소 형식이 이상합니다` 줄이 따로 나옵니다.

### 키워드 바꾸기

같은 파일의 `include_keywords`(포함) / `exclude_keywords`(제외)를 고칩니다.
**제외 키워드가 포함 키워드보다 우선**입니다. 제목에 제외 키워드가 하나라도 있으면 무조건 버립니다.

공고가 너무 많이 오면 → 포함 키워드를 줄이거나 제외 키워드를 늘리세요.
공고가 너무 안 오면 → `require_keyword: false` 로 바꾸면 키워드와 무관하게 전부 옵니다.

### 기관 추가 / 빼기

`institutions.yaml` 에서 `enabled: false` 로 바꾸면 그 기관은 건너뜁니다.

새 기관을 추가할 때는 세 줄이면 됩니다:

```yaml
  - id: 아무거나_영문
    name: 기관 이름
    url: "공고 목록 페이지 주소"
```

선택자는 안 적어도 됩니다. 범용 파서가 목록을 자동으로 찾습니다.
자동 인식이 안 되면 진단에서 ⚠️로 나오고, 그때 선택자를 추가하면 됩니다.

### 누적 기록을 처음부터 다시 쌓기

**Actions → 누적 기록 초기화 → Run workflow** → 확인란에 **`RESET`** 입력 → 실행

| 선택지 | 지우는 것 | 결과 |
|---|---|---|
| 전부 | `state/seen.json` + `state/archive.csv` + `공고누적.xlsx` | 최근 10일치 공고가 전부 신규로 다시 잡힙니다 |
| 누적 목록만 | `state/archive.csv` + `공고누적.xlsx` | 발송 이력은 유지 — 앞으로 새로 오는 공고만 누적됩니다 |

> **'전부'를 고르면 다음 메일 한 통이 아주 두껍습니다.** 최근 10일치 공고를 처음 보는 것으로
> 취급하기 때문입니다(보통 30~60건). 그 다음 실행부터는 다시 평소대로 돌아옵니다.

`RESET` 을 정확히 입력하지 않으면 실행되지 않습니다. 실수로 이력을 날리는 것을 막기 위한 장치입니다.

**직접 지우고 싶으면** GitHub 웹에서 파일을 열고 휴지통 아이콘 → Commit:
- `state/archive.csv` — 삭제
- `공고누적.xlsx` — 삭제
- `state/seen.json` — 내용을 `{"items": {}}` 로 바꾸기 (삭제해도 됩니다)

### 발송 시각 바꾸기

`.github/workflows/daily-brief.yml` 의 cron을 고칩니다. **UTC 기준**이라 한국시간에서 9를 빼야 합니다.

| 원하는 한국시간 | cron |
|---|---|
| 평일 10:00 | `0 1 * * 1-5` ← 현재 |
| 평일 09:00 | `0 0 * * 1-5` |
| 평일 08:00 | `0 23 * * 0-4` (전날 UTC라 요일이 하루 밀립니다) |
| 매일 10:00 | `0 1 * * *` |

> UTC로 변환했을 때 **자정을 넘어가면 요일도 하루 당겨야** 합니다.
> 10:00 KST = 01:00 UTC 라 같은 날이므로 `1-5`(월~금)가 그대로 맞습니다.
> 08:00 KST = 23:00 UTC 전날 이라 `0-4`(일~목)가 됩니다.

> GitHub Actions의 예약 실행은 서버가 붐빌 때 5~20분 늦어질 수 있습니다. 정시 보장은 안 됩니다.

## 마감된 공고를 걸러내는 방법

게시판 **목록에 마감일이 없는 기관이 20곳** 넘습니다. 그래서 마감일을 세 군데에서 순서대로 찾습니다.

| 순서 | 어디서 | 예 |
|---|---|---|
| 1 | 목록 행의 접수기간 컬럼 | `접수기간 : 2026.09.07 ~ 2026.09.30` |
| 2 | **공고 제목** | `컨설팅 사업 공고 (~9.16.(수) 까지)` |
| 3 | **공고 상세 페이지** | 1·2에서 못 찾은 것만 실제로 열어봅니다 |

3번은 **키워드·기간 필터를 통과한 공고에만** 적용합니다. 수집 단계에서 전부 열면 하루 400건이 넘지만, 필터 뒤에는 보통 10~40건이라 실행 시간이 1~2분 늘어나는 선에서 끝납니다.

**이런 것도 구분합니다**

- `접수마감`, `모집 종료`, `마감되었습니다` → 마감으로 판정
- `마감임박`, `마감일`, `마감기한` → 마감 **아님** (오탐 방지)
- `상시모집`, `예산 소진 시까지`, `선착순 마감` → `상시모집` 으로 표시하고 제외하지 않음
- 연도 없는 날짜(`9.16`)는 기준일 근처로 해석, 과거로 나오면 다음 해로 판단

**실행 로그에 결과가 찍힙니다**

```
-- 마감일 확인 23건 → 찾음 18, 상시 2, 마감확인 1, 실패 2
-- 마감 확인되어 제외: 4건
```

**여전히 못 잡는 경우** — 상세 페이지가 JavaScript로 그려지거나 마감일이 첨부 HWP 안에만 있으면 판정이 안 됩니다. 이런 공고는 `마감일 확인필요` 로 표시되어 그대로 옵니다.

마감 공고가 **한 건도 오면 안 되는** 상황이면 `config.yaml` 에서:

```yaml
unknown_deadline: exclude
```

대신 마감일 표기가 없는 정상 공고도 함께 빠집니다. 상시모집은 유지됩니다.

## 파서가 목록을 찾는 방법

기관마다 HTML이 다 달라서 선택자를 34개 다 지정하면 관리가 안 됩니다. 그래서:

1. 페이지의 모든 `<tr>` / `<li>` 중 **더 이상 중첩되지 않고 링크를 가진 것**을 후보 행으로 봅니다
2. 같은 부모를 가진 행들을 **한 그룹**으로 묶습니다
3. **날짜를 가진 행이 많은 그룹**에 높은 점수를 줍니다 (게시판 목록엔 날짜가 있고, 메뉴엔 없습니다)
4. 최고점 그룹을 공고 목록으로 채택합니다

날짜 해석도 자동입니다:
- `2026-09-07 ~ 2026-09-30` 처럼 붙어 있는 두 날짜 → 접수기간으로 보고 뒤쪽을 마감일로
- 기간 밖에 날짜가 하나 더 있으면 → 그게 게시일
- `26.09.05` 같은 2자리 연도도 처리

자동 인식이 안 되는 기관만 `institutions.yaml` 에 `row_selector` 등을 적어주면 됩니다.

## 2차 진단 결과 (v1.1) → v1.2에서 수정

33곳 중 **27곳 정상**. 전북테크노파크·저출산고령사회위원회가 살아났고, 제목·게시일 수정도 확인됐습니다.

| 증상 | 어디서 | 원인 | 수정 |
|---|---|---|---|
| 멀쩡하던 곳이 **0건으로 회귀** | NIPA | 첨부파일 판별을 `class` 이름으로도 했는데, 본문 링크에 `down`/`file` 이 든 class가 붙어 있어 제목이 통째로 걸러짐 | class 기준 판별 삭제. 그리고 **모두 걸러지면 필터 없이 다시 고르는 안전장치** 추가 |
| 게시일이 **2026-12-31** | 전북테크노파크 | 목록에 게시일이 없고 `마감 2026-12-31 18:00` 만 있는데 그걸 게시일로 씀 | 날짜 앞의 `마감`·`종료` 표시를 읽어 마감일로만 쓰고 게시일에서는 제외 |

진단에 `--dump`가 들어 있어, 다시 돌리면 실패한 기관의 원본 HTML이 **Artifacts의 `out/html/`** 에 저장됩니다. 로그가 아니라 **Artifacts**를 받아야 이 파일이 들어 있습니다.

## 문제가 생겼을 때

**메일이 안 와요**
Actions → 최근 실행 → 로그를 봅니다. `SMTP 미설정` 이면 Secrets를 등록하세요.
`Username and Password not accepted` 면 앱 비밀번호가 아니라 일반 비밀번호를 넣은 것입니다.

**같은 공고가 또 왔어요**
사이트가 상세 URL을 매번 다르게 주는 경우입니다. 해당 기관에 `detail_url`을 지정해야 합니다.

**공고가 하나도 안 와요**
`--dry-run` 으로 실행해 로그의 `수집 N → 채택 M` 줄을 보세요.
`키워드없음`이 크면 포함 키워드가 좁은 것이고, `제외키워드`가 크면 제외 목록이 넓은 것입니다.

**한 기관만 계속 실패해요**
`institutions.yaml` 에서 `enabled: false` 로 꺼두면 나머지는 정상 동작합니다.
